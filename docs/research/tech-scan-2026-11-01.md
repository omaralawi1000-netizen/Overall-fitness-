# Aven 2 Tech Scan

_Research brief · 1 Nov 2026. Saved from Omar's research artifact (https://claude.ai/artifact/EkzYSZTuGftXgjfPYH724Y) on 1 Nov 2026._

What to adopt, test, park or skip for a coach-first training, wrestling and food app on a 120 Hz Galaxy, with iPhone friends, Danish and English, and no backend. Every price is per month in DKK at 6.65 DKK per USD. Things I couldn't verify are marked.

Verdicts: Adopt now · Test · Later · Skip.

## Five things that change plans

1. **Gemini's own terms limit how friends can use it** EEA users need paid services, users must be 18+, and no medical advice. Friends should use billing-enabled keys (pennies). If any friend is under 18, Gemini is off-limits for them. Sources: [Gemini API terms, modified 28 Apr 2026](https://ai.google.dev/gemini-api/terms)

2. **Gemini 3.8 Flash doubles in price on 1 Jan 2027** From $0.75/$3.75 to $1.50/$7.50 per million tokens. Your usage goes from about 40 to about 81 DKK a month. Sources: [Gemini pricing page, updated 30 Oct 2026](https://ai.google.dev/gemini-api/docs/pricing)

3. **Claude Haiku 5.5 is about 15 times cheaper** $0.10/$0.50 per million tokens: about 5 DKK a month for the same usage. Its Danish is untested, so let the Coach exam decide. Sources: [Anthropic pricing page, checked 1 Nov 2026](https://platform.claude.com/docs/en/about-claude/pricing)

4. **Danish-trained speech models beat the big names** On an independent leaderboard (Oct 2026), syv-transcribe (7.1% error) beats ElevenLabs (13%) and OpenAI (16.5%). Gemini and Groq weren't tested. Your own 30-clip test decides. Sources: [Danish ASR leaderboard (rows to 23 Oct 2026)](https://huggingface.co/datasets/RyeAI/danish-asr-leaderboard)

5. **Motion 14 runs springs on the compositor** Released 29 Oct: hardware-accelerated springs with velocity handoff and overdamped springs. That's the catchable, no-overshoot feel you described. Sources: [Motion changelog (14.8.0, 29 Oct 2026)](https://motion.dev/changelog)

## A. Visual and motion

Your blur test plan already exists. These add evidence and tools to it, not a second plan.

### Adopt now

#### Motion 14 for all interactive motion

Released 29 Oct 2026. Springs and single transforms (x, y, scale) now run hardware-accelerated, velocity carries over when a spring is interrupted, and springs can be overdamped (negative bounce). That is exactly 'calm, no overshoot, catchable'. Lesson 6 says script animation hit 60 fps and browser-driven hit 120, so this matters.

Sources: [Motion changelog (14.8.0, 29 Oct 2026)](https://motion.dev/changelog)

- Evidence: High (primary changelog)
- Cost/mo: 0 DKK
- Effort: Low: Claude writes it
- Risk: Medium: 14.x is weeks old. Pin the version. Layout animations fall back to the CPU when interrupted (14.7.1).

#### CSS linear() springs for simple one-way transitions

Bakes a spring curve into plain CSS, so press dips and fades run on the compositor with zero JavaScript. Use Motion when a gesture can catch it; use linear() when nothing can.

Sources: [Chrome docs: CSS linear() easing](https://developer.chrome.com/docs/css-ui/css-linear-easing-function) · [Josh Comeau: springs in native CSS](https://joshwcomeau.com/animation/linear-timing-function)

- Evidence: High (Chrome docs)
- Cost/mo: 0 DKK
- Effort: Low
- Risk: Low. Can't be caught mid-motion with velocity.

#### Haptics as a bonus, never a signal

Android Chrome supports navigator.vibrate. iPhone Safari has no vibration API in 2026; the only route is an unofficial hidden-switch trick that WebKit could remove. Feature-detect, vibrate on Android, and make every tap fully readable without haptics.

Sources: [web-haptics browser support notes](https://www.mintlify.com/lochie/web-haptics/advanced/browser-support) · [azukiazusa: iOS Safari web haptics](https://azukiazusa.dev/en/blog/ios-safari-web-haptics)

- Evidence: Medium (several dev sources agree, no Apple statement)
- Cost/mo: 0 DKK
- Effort: Low
- Risk: Low on Android. The iOS trick may break without warning.

### Test

#### Add two facts to the blur test

1) Chrome 129 changed how backdrop-filter samples past its edges (mirror instead of duplicating edge pixels), which was the cause of edge flicker on scroll. Test on today's Chrome, not old notes. 2) No primary source documents noise or dither as a banding fix on Android Chrome. That is why your test, not a library, has to decide method B.

Sources: [Chromium intent: backdrop-filter edge mode (Chrome 129)](https://groups.google.com/a/chromium.org/g/blink-dev/c/ZtMnFCHZhMQ) · [James Fisher: backdrop blur without flicker](https://jameshfisher.com/2024/04/23/backdrop-blur-without-the-flickering/)

- Evidence: Medium (Chromium intent; banding fix unverified)
- Cost/mo: 0 DKK
- Effort: Medium (one test page)
- Risk: Low

#### View Transitions for screen and tab changes

Same-document transitions work in Chrome 111+, Safari 18+ and Firefox 144+. They snapshot elements as flat images, so live blur behind a moving snapshot freezes during the transition, and snapshots add layers mid-animation (lesson 3: black frames). Motion's AnimateView wraps React's own ViewTransition (needs React 19.3). Try it on one transition and film it before using it everywhere.

Sources: [Chrome docs: View Transition API](https://developer.chrome.com/docs/web-platform/view-transitions) · [Motion changelog (14.8.0, 29 Oct 2026)](https://motion.dev/changelog) · [Interop 2026 announcement, 12 Feb 2026](https://web.dev/blog/interop-2026)

- Evidence: High for support, unknown for blur
- Cost/mo: 0 DKK
- Effort: Medium
- Risk: Medium: black frames and frozen glass are possible.

#### Scroll-driven animations for headers and progressive edges

Chrome since 115, Safari 26 (threaded since 26.4). Firefox still behind a flag, but it's an Interop 2026 focus. Runs off the main thread, so scroll-linked fades stay smooth.

Sources: [Scroll-driven animations cross-browser (2026)](https://www.buildmvpfast.com/blog/css-scroll-driven-animations-replace-js-2026) · [WebKit: Safari 26.0 features](https://webkit.org/?p=17333)

- Evidence: Medium (secondary source plus WebKit notes)
- Cost/mo: 0 DKK
- Effort: Low
- Risk: Low. Needs a static fallback for older Firefox.

#### NumberFlow for the rest timer and record numbers

Odometer-style digit animation for React (@number-flow/react). Good fit for the rest timer, a new record and totals. Measure it at 120 Hz on Beta before it goes near the live workout.

Sources: [NumberFlow on GitHub](https://github.com/barvian/number-flow)

- Evidence: Medium (GitHub project)
- Cost/mo: 0 DKK
- Effort: Low
- Risk: Low

#### WebGL glass as spare method F

liquidGL and @el-gladiador/liquid-glass-react do refraction and in-shader blur. Both capture page content as a picture, so they only suit glass over a background you draw yourself. No 2026 maintenance dates found.

Sources: [liquidGL docs](https://docsearch.algolia.com/mcp/docs/repo/naughtyduk/liquidgl) · [@el-gladiador/liquid-glass-react](https://www.pkgstats.com/pkg:@el-gladiador/liquid-glass-react)

- Evidence: Low (no dates, small packages)
- Cost/mo: 0 DKK
- Effort: High
- Risk: High: battery, maintenance, DOM capture limits.

### Later

Sources: [web.dev: WebGPU in major browsers](https://web.dev/blog/webgpu-supported-major-browsers)

- Evidence: Low (judgment)
- Cost/mo: 0 DKK
- Effort: Low
- Risk: Low

### Skip

#### GSAP or Lottie next to Motion and Rive

Two runtimes doing the same job means two springs that never quite match. Motion plus Rive already cover it.

- Evidence: Judgment
- Cost/mo: 0 DKK

## B. Coach intelligence

Costs below assume 30 Coach calls a day, 4,000 tokens in and 1,000 out each (thinking included), no caching. 1 USD ≈ 6.65 DKK (20 Oct 2026).

### Adopt now

#### One small model adapter, and run the exam on 2–3 models

Prices moved a lot this autumn. Gemini 3.8 Flash doubles on 1 Jan 2027, and Claude Haiku 5.5 is now far cheaper per token. A thin adapter (same tools, same strict JSON schemas, any provider) lets the exam pick the model instead of habit.

Sources: [Gemini pricing page, updated 30 Oct 2026](https://ai.google.dev/gemini-api/docs/pricing) · [Anthropic pricing page, checked 1 Nov 2026](https://platform.claude.com/docs/en/about-claude/pricing)

- Evidence: High (both price pages)
- Cost/mo: 0 DKK to build
- Effort: Medium: one Claude session
- Risk: Low

#### Prompt-injection rule: outside text can never act

The 2025 'design patterns' paper (Google DeepMind's CaMeL among them) says the only reliable defence is structural: once untrusted text is in context, it must not be able to trigger an action. For Aven 2 that means web pages, food labels, recipe text and photo text are data. They can't write memory, change targets or call a tool. Keep the action allow-list and Undo in code. This also closes spec defect 6.

Sources: [Design Patterns for Securing LLM Agents (arXiv 2506.08837)](https://arxiv.org/abs/2506.08837) · [Willison on the patterns paper, Jun 2025](https://simonwillison.net/2025/Jun/13/prompt-injection-design-patterns/)

- Evidence: High (peer-reviewed paper, widely cited)
- Cost/mo: 0 DKK
- Effort: Low
- Risk: Low

#### Own memory store, built like a timeline

The memory products bet on different ideas: Mem0 extracts facts, Zep keeps a timeline graph, Letta lets the agent edit files. Their benchmark numbers conflict and come from the vendors themselves. Take the design idea that fits a coach: every fact has a scope (one-off or standing), valid-from and valid-until dates, a last-seen date and a source. Keep it on the phone. This fixes spec defects 1 and 3.

Sources: [Mem0 vs Zep vs Letta compared, Aug 2026](https://www.digitalapplied.com/blog/open-source-agent-memory-mem0-letta-zep-compared) · [Atlan: agent memory frameworks 2026](https://atlan.com/know/best-ai-agent-memory-frameworks-2026/)

- Evidence: Medium (design patterns solid, numbers vendor-run)
- Cost/mo: 0 DKK
- Effort: Medium
- Risk: Low

### Test

#### Claude Haiku 5.5 vs Gemini 3.8 Flash vs Gemini 3.5 Flash-Lite

Per month at the usage above: Haiku 5.5 ≈ 5 DKK ($0.10 in / $0.50 out per million). Gemini 3.5 Flash-Lite ≈ 22 DKK. Gemini 3.8 Flash ≈ 40 DKK now and ≈ 81 DKK from January. - Evidence: High for prices; Danish quality untested
- Cost/mo: 5–81 DKK per person
- Effort: Medium
- Risk: Medium: one source says Haiku 5.5 uses about 30% more tokens for the same text.

#### A notice engine in code, the model only words it

The loudest 2026 complaints: Google's Fitbit coach invented workouts and gave odd advice, and WHOOP's coach is called pushy and wordy ('keeps proposing plans'). So code picks what's worth saying (how important, how sure, not said recently, still fresh), with an expiry date. The model just phrases it, briefly, with at most one question.

Sources: [TechRadar: Fitbit Gemini coach complaints (2026)](https://techradar.com/ai-platforms-assistants/fitbits-gemini-ai-coach-is-giving-users-unhinged-fitness-advice-heres-why-users-are-saying-they-cannot-wait-for-my-trial-to-end) · [Android Authority: Google health coach hallucinations](https://androidauthority.com/google-health-coach-hallucinations-3667257/) · [Gear Patrol: WHOOP AI user feedback](https://www.gearpatrol.com/fitness/whoop-ai-reddit-user-feedback-pros-cons/) · [WHOOP community: 'Coach AI is getting worse'](https://www.community.whoop.com/t/whoop-coach-ai-is-getting-worse/16360)

- Evidence: Medium (press and forum reports, not studies)
- Cost/mo: 0 DKK
- Effort: Medium

#### Promptfoo only if the exam harness hurts

OpenAI bought Promptfoo in March 2026 and says the CLI stays MIT open source. You already have exam/v1, so only switch if the home-made one gets painful. Langfuse is the open alternative, but it wants a server.

Sources: [OpenAI acquires Promptfoo (Mar 2026)](https://securityboulevard.com/2026/03/openai-acquires-security-startup-promptfoo-to-fortify-ai-agents)

- Evidence: High (deal), Medium (future openness)

- Effort: Medium
- Risk: Low

Sources: [Chromium forum: built-in AI on Chrome for Android](https://groups.google.com/a/chromium.org/g/chrome-ai-dev-preview-discuss/c/HKIndTczlPM)

### Skip

#### Hosted memory services (Mem0 cloud, Zep cloud)

Needs a backend and sends health memories to another company, to win on benchmarks those vendors ran themselves.

#### Multi-agent Coach

More calls, more latency, more places to disagree. One Coach with good tools and code-side rules is enough.

- Evidence: Judgment

## C. Voice

The best evidence this year is an independent Danish speech leaderboard. It changes the picture, but it doesn't test Gemini, Groq or gym phrases.

### Adopt now

#### A personal voice test set before choosing

Record 30 short clips: you plus one or two friends, mixed Danish and English, with numbers and units ('8 på 80', '200 g skyr', 'move pull day to torsdag'). Run every candidate below and score words and numbers separately. The leaderboard uses read-aloud and conversation sets, not gym commands, and leaves out Gemini and Groq.

Sources: [Danish ASR leaderboard (rows to 23 Oct 2026)](https://huggingface.co/datasets/RyeAI/danish-asr-leaderboard)

- Evidence: High (method)
- Cost/mo: Under 5 DKK
- Effort: Low: Claude builds the script
- Risk: Low

#### Keep tap-to-talk and fix numbers in code

Old Aven's lessons still hold: phone mic, tap to listen, never always-on, and a hint list of exercise names and Danish brands. Turn spoken numbers and units into data with code, not the model.

- Evidence: High (your own lessons 11–16)
- Cost/mo: 0 DKK
- Effort: Low
- Risk: Low

#### Voice timing targets

Aim for first sound back within about 800 ms, show the words live while you speak, and let a tap on the orb stop the Coach mid-sentence. Voice-agent guides agree that good interruption handling beats raw speed.

Sources: [Picovoice: latency, turn-taking, barge-in](https://picovoice.ai/guide/voice-agents/voice-ux-latency-turn-taking/) · [Turn-taking 250 ms threshold (May 2026)](https://tianpan.co/blog/2026-05-10-voice-agent-turn-taking-250ms-threshold-reshapes-architecture)

- Evidence: Medium (vendor guides, consistent)
- Cost/mo: 0 DKK
- Effort: Medium
- Risk: Low

## D. Food

Open Food Facts is already covered (about 16–17k Danish products). New ground only.

### Adopt now

#### Barcode scanning: native first, WASM fallback

Use the browser's BarcodeDetector where it exists (Chrome for Android, through Play services) and the barcode-detector polyfill (ZXing compiled to WebAssembly) on iPhone. Feature-detect at runtime. MDN still marks the API experimental.

Sources: [MDN: Barcode Detection API](https://developer.mozilla.org/docs/Web/API/Barcode_Detection_API) · [barcode-detector polyfill (ZXing WASM)](https://orbisk.github.io/vue-use-barcode-detection/compatibility)

- Evidence: Medium (MDN plus polyfill docs)
- Cost/mo: 0 DKK
- Effort: Low
- Risk: Low

#### Photo estimates ask for one anchor

Studies find about 40% average error on weight and calories from photos (ChatGPT, Claude), worse for Gemini in one 52-food test, and over 60% error on protein. Giving the total weight cut error from about 51% to about 29%. So after a photo, the Coach asks one thing: a weight, or 'is that a 500 ml bowl?'. It's always shown as an estimate.

Sources: [Nutrients: ChatGPT-5 food estimates with context (2025)](https://www.mdpi.com/2072-6643/17/22/3613) · [Virginia Tech: multimodal LLM nutrition evaluation](https://vtechworks.lib.vt.edu/items/b67c2a61-f283-41ba-9602-9798306b9529) · [Biolayne review of the 52-food LLM study](https://biolayne.com/reps/issue-44/can-we-use-ai-to-accurately-track-calories-with-a-picture/)

- Evidence: Medium–High (peer-reviewed 2025 papers)
- Cost/mo: Under 1 DKK per photo
- Effort: Low
- Risk: Low

## E. Platform

### Adopt now

#### Stay PWA plus a Capacitor 8 wrapper

Capacitor 8 came out in Dec 2025 and was at 8.3.x by spring 2026. It gives you local notifications, Health Connect and background work on Android while every screen stays web, where Claude can see and judge it. A native or React Native rebuild would redo the UI for no gain in motion.

Sources: [Ionic: Announcing Capacitor 8 (Dec 2025)](https://www.plushcap.com/content/ionic/blog/ionic-announcing-capacitor-8) · [Capacitor 8.3.1 release (16 Apr 2026)](https://newreleases.io/project/github/ionic-team/capacitor/release/8.3.1)

- Evidence: High (releases)
- Cost/mo: 0 DKK (Play listing 25 USD once, if ever)
- Effort: Medium
- Risk: Low

#### IndexedDB plus storage.persist() plus file backup

Ask for persistent storage once there's real data. Chrome grants it to installed PWAs. Safari exempts Home Screen web apps from its 7-day deletion of site data. Keep the manual backup file in phase 1 anyway.

Sources: [web.dev: Storage for the web](https://web.dev/articles/storage-for-the-web) · [WebKit: Updates to Storage Policy](https://webkit.org/blog/14403/updates-to-storage-policy/)

- Evidence: High (web.dev, WebKit)
- Cost/mo: 0 DKK
- Effort: Low

#### Notifications: Capacitor local notifications on Android

Scheduled on the phone, no server. That covers your phone. For iPhone friends, see Web Push below.

### Later

## G. Product and UX

### Adopt now

#### Design for day 1 to day 100

A 2024 JMIR review of 18 studies: a median 70% of users quit within 100 days, most of them early. It found 22 reasons in six groups: technical problems, privacy, poor experience, content, time or cost, and changing needs. So instant logging, a great first week, and a clear 'what's next' when a goal is reached (people also leave after winning).

Sources: [JMIR 2024: app abandonment scoping review](https://www.jmir.org/2024//e56897) · [eMarketer: AI and health app growth](https://www.emarketer.com/content/ai-will-power-next-phase-of-health-app-growth)

- Evidence: High (peer-reviewed review)
- Cost/mo: 0 DKK

#### Coach rules from real 2026 complaints

Never invent history (Google's coach did). Keep replies short and ask at most one question (WHOOP's coach is called wordy and pushy). Stay silent unless it matters. Food logging uses neutral words, no red 'over' states: a 2025 study found users feel shame logging unhealthy food (reported second-hand).

Sources: [Android Authority: Google health coach hallucinations](https://androidauthority.com/google-health-coach-hallucinations-3667257/) · [Gear Patrol: WHOOP AI user feedback](https://www.gearpatrol.com/fitness/whoop-ai-reddit-user-feedback-pros-cons/) · [eMarketer: AI and health app growth](https://www.emarketer.com/content/ai-will-power-next-phase-of-health-app-growth)

- Evidence: Medium (press, forums, one study second-hand)

## H. Privacy

None of this is legal advice. It's what the primary texts say and where the grey areas are.

### Adopt now

#### Friends need a billing-enabled Gemini key

Google's terms (modified 28 Apr 2026) say you may use only paid services when making an app available to users in the EEA, Switzerland or the UK. Users must be 18+, the API is 'for professional or business purposes, not for consumer use', and it may not be used to give medical advice. Upside: in the EEA, Google applies its paid data terms even to free quota, so free use there isn't used for training.

Sources: [Gemini API terms, modified 28 Apr 2026](https://ai.google.dev/gemini-api/terms)

- Evidence: High (primary terms)
- Cost/mo: A few DKK a month per friend
- Effort: Low: a setup note
- Risk: High if ignored

#### Stay serverless so health data never reaches you

If each person's data goes only from their phone to the AI provider they chose with their own key, you never hold anyone's health data. That keeps you about as far from GDPR controller duties for Article 9 data as an app can be. Add a plain in-app page: what is sent to Google or Anthropic, and when.

Sources: [Legiscope: health data under Article 9](https://www.legiscope.com/blog/health-data-article-9-gdpr.html)

- Evidence: Medium (my reading of GDPR, not a ruling)
- Cost/mo: 0 DKK
- Effort: Low
- Risk: Low

#### Lock down each API key

Keys stay on the phone, never in backups unless the person opts in, never in logs, and are shown masked. Ask friends to make a separate key, restrict it to the Gemini API and to the app's web address (Google Cloud key restrictions), and set a spend cap.

Sources: [Google Cloud: API key restrictions](https://cloud.google.com/docs/authentication/api-keys#adding-application-restrictions)

- Evidence: High (Google Cloud docs)
- Cost/mo: 0 DKK
- Effort: Low
- Risk: Low

#### Say the Coach is an AI

EU AI Act Article 50(1) chatbot disclosure has applied since 2 Aug 2026 and was not delayed by the Digital Omnibus. Labelling AI-generated content got a transition to 2 Dec 2026 for systems already on the market. One line in onboarding covers you.

Sources: [Goodwin: AI Act transparency in force, Aug 2026](https://www.goodwinlaw.com/en/insights/publications/2026/08/alerts-technology-dpc-eu-ai-act-transparency-obligations-now-in-force) · [Ropes & Gray on Art. 50, Aug 2026](https://www.ropesgray.com/en/insights/viewpoints/102nfqm/you-talkin-to-me-operationalising-the-eu-ai-acts-transparency-obligations)

- Cost/mo: 0 DKK
- Effort: Low
